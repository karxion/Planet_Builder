# 던전 전용 에셋 제작 검토안

상태: **이번 작업은 제작 설계이며 새 이미지를 생성하지 않았다.** [던전 v2 설계](./dungeon-v2.design.md)에 맞춘 32종의 에셋 슬롯과 우선 16종을 제안한다. 기존 파일 재사용을 포함하며 모두 신규 제작한다는 뜻은 아니다. 단순 색/상태 변형은 별도 종수로 세지 않는다. [지저·해저 64종 목록](./subsurface-object-assets.catalog.md)의 1차 24종은 이미 제작·통합됐고 나머지 40종은 확장안이다.

## 1. 제작 방식과 규격

- **이미지 생성 도구로 개별 래스터 PNG를 제작**한다. 완성된 던전 한 장이나 여러 종류의 오브젝트를 한 이미지에 묶어 대체하지 않는다. SVG로 그린 도형을 신규 이미지 에셋이라고 보고하지 않는다.
- 투명 배경을 기본으로 한다. 바닥 타일은 연결되는 정사각형 텍스처가 필요하므로 해당 부분만 불투명/반복 가능한 경계로 만들 수 있다. 벽·계단·가구는 바닥 배경과 장식 받침대를 포함하지 않는다.
- `T`는 전투지도용 수직 탑다운, `D`는 탑다운+조감도다. D는 기존 파이프라인처럼 같은 물체의 두 시점을 한 마스터에 만들 수 있다. 시점의 뷰포트·앵커는 별도 기록한다. 효과/바닥/평면 룬에 불필요한 조감도를 강제하지 않는다.
- 에셋 배포본은 원본 가로·세로의 **약 2/3**다. 원본 크기·해시를 보관하고 원본에서 한 번만 축소한다. 완성 지도 PNG는 기존 **한 변 최대 3000px**를 유지한다.
- 스타일은 현재 지도와 어울리는 채색된 판타지 석조 부품으로 통일한다. 탑다운은 기울어진 원근 없이, 조감도는 동일한 카메라/빛 방향으로 맞춘다. 광원/그림자는 인접 칸을 가리지 않도록 짧게 제한한다.
- 이미지에 글자·수치·격자·방 번호·경고 삼각형·원형 배지를 넣지 않는다. 기믹 이름과 GM 표시/플레이어 공개 상태는 지도 UI가 담당한다.
- 아래 점유 크기는 **권장 기본 footprint**이며 최종 게임 크기는 메타데이터로 정한다. 이미지 높이/투명 여백이 점유를 바꾸지 않는다. 벽/문/교각의 연결 면과 바닥 접점은 같은 규격을 사용한다.

## 3. 재사용과 중복 제작 방지

| 던전 항목 | 기존/계획 에셋과의 관계 | 처리 |
| --- | --- | --- |
| D01/D03/D06 | 기존 `scene-maps` paving/wall/gate | 현재 파일을 검수용 대체물로 사용 가능. 던전 축척·문의 바닥 접점이 맞는지 별도 확인 |
| D09/D10 | 제작된 `subsurface/c02.png` 하강 계단 | 조감도를 재사용하고 상승/하강 식별과 탑다운 방향을 검수. 필요할 때 해당 시점만 수정 |
| D28 | 제작된 `subsurface/c04.png` 관문 | 프레임을 공유하고 활성 효과/세계 공간 소속은 별도 |
| D32 | 제작된 `subsurface/c01.png` 석교 | 연결 단면·폭을 공통화하고 난간/재질 변형만 추가 |
| D03/D07 | 지저 US05/US06 성벽·성문 | 건축 규모가 다른 항목은 무조건 축소하지 않음. 던전용 접속부가 맞을 때만 재사용 |

공용 PNG 24종은 [manifest](../../src/data/subsurface-image-manifest.json)와 [제작 보고서](../04-report/subsurface-assets-2026-10-29.md)에 등록돼 있다. 현재 지역 렌더러는 왼쪽 조감도 절반을 사용한다. 오른쪽 시점은 일부 입면 표현이 있어 던전의 정밀 탑다운/통행 규격에 맞는지 검수하고 필요하면 해당 시점을 이미지 생성 도구로 수정한다. 지역 지도에 연결됐다는 사실과 던전 편집/기믹 통합 완료는 구분한다. 파일이 있는 항목은 기존 ID를 참조하고 중복 파일을 만들지 않는다.

## 4. 생성·검수 절차

1. 목록·시점·점유·연결 면·상태 변형을 먼저 확정한다. 도구 생성 원본과 사용본의 경로를 나눈다.
2. **D03 석벽, D09 계단, D24 수정** 샘플로 재질/카메라/가독성을 맞춘다. 세 항목은 우선 16종에 포함된다.
3. 한 번에 한 종류씩 생성한다. D 시점 마스터도 같은 오브젝트의 두 시점만 포함한다. 상태 변형은 기준 물체를 참조해 동일한 실루엣·앵커를 유지한다.
4. 원본을 검수하고 필요하면 이미지 생성 도구로 수정한다. 이후 배포본만 약 2/3 축소한다. 크기 맞춤 때문에 이미 축소된 파일을 다시 축소하지 않는다.
5. 밝은/어두운 바닥에서 32/64px 표시와 전투지도 확대를 확인한다. 열린 문/계단/구덩이가 방향과 역할을 전달하는지 확인한다.
6. 90° 회전, 벽·문·계단 연결, 1칸 출입구·2칸 복도, 큰 개체 footprint, 선택 범위를 확인한다.
7. GM 비공개·플레이어 공개·PNG/SVG 내장 출력을 검수한다. 감춰진 함정의 이미지/상태 변형을 플레이어용 내보내기에 남기지 않는다.

## 5. manifest 필수 정보

`assetId`, `family`, 허용 재질/환경 태그, 원본/배포 크기와 SHA-256, 시점별 crop/anchor, 칸 단위 footprint, 허용 회전, 연결 면과 힌지, 표현 상태별 파일 참조, 기본 레이어와 겹침 순서를 기록한다.

기본 충돌 형상은 독립된 선언 데이터다. `blocksMovement`, `blocksSight`, `movementCost` 및 상태별 변경을 엔티티가 참조한다. 예를 들어 내려간 쇠살문은 통행을 막지만 시야를 완전히 막는 석벽과 다르다. 결계 역시 통행 차단/시야 차단/특정 대상 차단을 개별 속성으로 둔다.

이미지 제작 완료, 렌더링 통합 완료, 기믹 동작/저장 완료를 각각 보고한다. 멋진 그림이 추가된 상태를 기능 구현 완료로 취급하지 않는다.
