# 판타지 행성 빌더 평가 및 개선 방향

## 평가 기준

- 평가일: 2026-10-25.
- 대상: v1.1.0, 커밋 `d2e0a8a`. origin을 조회했으며 main과 동일한 커밋임을 확인했다.
- 방법: 소스·설계·기존 검증 보고서 검토, 단위 테스트 재실행, 타입 검사, 빌드, 현재 npm 보안 감사, 던전 425개 비교 표본.
- 이번에는 실제 브라우저·모바일 화면을 직접 검사하지 않았다. 과거 브라우저 접근 제한 때문에 완료하지 못한 화면 검증을 완료된 것으로 간주하지 않는다. UI 평가는 코드상 구조·상태 전이에서 추론한 사용성 위험이며, 화면 디자인의 실제 가독성 평가와 구분한다.
- 분석만 수행했다. 제품 코드·의존성·저장 데이터·공개 배포는 변경하지 않았다.

## 종합 판단

**기능은 풍부한 GM용 세계관 제작 베타이며, 안정적인 캠페인 운영 도구로 마무리하는 단계가 필요하다.**

지도·행정·NPC·종교·보물·던전을 한 프로젝트에서 다루는 점이 강점이다. 반면 기능별 생성 결과를 지속적으로 편집·복구·연결하는 흐름과 실제 플레이 난이도 검증은 생성 기능보다 미성숙하다. 다음 목표는 완전한 D&D 게임 엔진이나 VTT보다 **한국어 세계관 제작과 세션 준비 작업대**로 좁히는 것이 적합하다. 이는 제품 방향에 대한 판단이지 사용자 조사로 검증한 시장 결론은 아니다.

## 우선 개선 사항

### P1. 의존성 보안 감사 결과가 출시 당시와 달라졌다

- 현재 전체 감사는 패키지 항목 기준 11건(critical 4, high 6, moderate 1), 프로덕션 감사는 critical 1건이다. 항목 수는 독립적인 공격 경로 수나 이 앱의 취약점 수가 아니다.
- 프로덕션 항목은 고정된 `dompurify@3.4.16`이다. 현재 공지는 패치 버전 `3.4.17`을 안내한다.
- **실제 악용을 입증한 것은 아니다.** 가장 높은 경고는 `SAFE_FOR_TEMPLATES`, 특정 DOM 반환·shadow root·후속 템플릿 평가 조건을 요구하며 현재 정책에는 `SAFE_FOR_TEMPLATES`가 없다. 다른 공지의 `IN_PLACE` 및 XHTML 파서 모드도 현재 정책에 설정되어 있지 않다.
- 따라서 위험 범위 확인과 패치 업데이트·보안 회귀 테스트가 필요하다. 10월 18일의 "프로덕션 0건"은 당시 결과이며 현재 상태의 보증으로 재사용하면 안 된다.
- 개발 도구 Vite·Vitest 계열 경고는 정적 배포 앱과 노출 면이 다르다. 개발 서버·테스트 서버를 공개하지 않고 호환성 확인 후 각각 갱신한다.
- 근거: [package.json](../../package.json#L51), [정화 정책](../../src/services/content-sanitizer.ts#L4), [critical 공지](https://github.com/advisories/GHSA-cg2g-xh64-v4q7), [IN_PLACE 공지](https://github.com/advisories/GHSA-mrv2-3pqr-j5jr).

### P1. 자동 저장과 실제 편집 확정의 의미를 구분해야 한다

- 프로젝트 자동 저장은 `lastPlanetProject` 단일 키에 10초 유휴 후 기록한다. 프로젝트별 복구 목록이나 과거 세대 보존은 없다.
- NPC 상세의 입력값은 제출 시 `storedNpc`에 반영된다. 반면 앱은 문서 전체의 `change` 이벤트로 자동 저장을 예약한다. 상세 초안이 미확정인 상태에서도 마지막 확정 데이터만 저장하고 "자동 저장됨"을 표시할 수 있는 구조다.
- 종료 직전 변경의 보호를 위한 `beforeunload` 경고나 visibility/pagehide 기반 보완 처리는 이 저장 경로에서 확인되지 않는다. 모바일 종료 시 비동기 저장 완료를 보장할 수도 없다.
- 개선: `초안 수정 중 / 프로젝트 변경 / 로컬 보존 / 클라우드 반영`을 분리하고 닫기·선택 변경 시 초안 처리 정책을 통일한다. 저장 성공 여부와 실패 원인을 명확히 표시한다.
- 로컬 프로젝트 목록, 여러 세대 스냅샷, 복구 미리보기, 중요 파일 백업을 먼저 제공한다. 종료 이벤트에만 의존하지 않고 편집 확정 시점에 증분 상태를 보존한다.
- 근거: [자동 저장 이벤트](../../src/services/planet/planet-builder.ts#L164), [단일 복구 키](../../src/services/planet/planet-builder.ts#L19), [NPC 반영 시점](../../src/controllers/campaign-world.ts#L625).

### P1. 여러 기기의 클라우드 저장은 원자적 충돌 검사가 필요하다

- 현재는 원격 revision 조회 후 별도 PATCH를 보낸다. 두 클라이언트가 같은 revision을 읽으면 둘 다 갱신할 수 있다. 단일 브라우저 저장 큐로 해결되지 않는다.
- 개선: 서버의 조건부 갱신/CAS 또는 트랜잭션으로 예상 revision을 검사하고, 충돌 시 로컬본·원격본 비교 및 별도 사본 보존을 제공한다. 확인되지 않은 bkend API를 추정해 구현하지 않는다.
- 완료 기준: 실제 계정과 브라우저 2개에서 같은 프로젝트 동시 편집·저장 시 조용한 덮어쓰기가 없어야 한다. RLS·파일 소유권·로그아웃 후 접근도 실제 서버로 검증한다.
- 근거: [revision 조회](../../src/services/planet/bkend-repository.ts#L209), [조건 없는 PATCH](../../src/services/planet/bkend-repository.ts#L264).

### P1. 난이도 전환은 전투 구성의 일관성을 보장하지 않는다

- 난이도 상향 시 목표 CR 추첨이 같은 난수 스트림을 먼저 소비한다. 이후 상자·경비·함정 추첨이 달라져, 같은 지형이라도 경비 구성은 다시 뽑힌다.
- 17개 테마 × 시드 `audit-0`~`audit-24`, 테마별 첫 대표 몬스터로 **425개** 일반/도전적 쌍을 비교했다.
- 67개에서 비교용 전투 규모 대리값이 감소했고, 57개에서 금화 합계가 감소했다. 대리값은 `원본 CR XP × 개체 수 × HP 배율 × 피해 배율`의 합이며 **공식 XP·조우 난이도 계산이 아니다**. 금화의 단조 증가 역시 기존 요구사항은 아니므로 개선 판단 자료로만 사용한다.
- 재현 사례: `alien-ruin`, `aboleth`, `audit-0`은 방 20개가 동일하지만 일반 12개체에서 도전적 10개체로 줄어든다. 목표 CR은 10→11, 보스 HP·피해는 각각 ×1.1, 함정은 1→2다. 이 사실만으로 실제 전투가 반드시 쉬워진다고 단정할 수는 없지만 "상향"의 의미가 일관되지 않다.
- 개선: 지형·기본 거주 집단·보상·난이도 변형의 난수 스트림을 분리한다. 기본 구성을 보존한 뒤 상향 요소를 적용하고, 파티 인원·레벨·판본·휴식 조건을 입력받아 방별 조우를 평가한다.
- HP·피해 보정만으로 공식 CR이 검증되는 것은 아니다. 원본 CR, 창작 보정, 파티 예상 난이도를 별도 표시하는 현재 원칙은 유지한다.
- 근거: [난수·목표 CR](../../src/generators/dungeon-interior.ts#L82), [보스 배율](../../src/generators/dungeon-interior.ts#L132), [경비 재추첨](../../src/generators/dungeon-interior.ts#L165).

### P2. 던전과 세계관 데이터는 생성 이후의 편집·관계 관리가 부족하다

- 내부 던전은 방·통로·배치 생성은 가능하지만 수동 방 편집, 몬스터 교체·재배치, 보상 회수·문/함정 상태·부분 공개 등 지속적인 세션 운영 상태가 부족하다.
- 31개 대표 몬스터 레퍼런스 중심이라 14개 유형이 있어도 조우 다양성은 제한적이다. 구체적인 공격·주문·저항·행동 비용을 일괄 계산하는 완전한 규칙 엔진은 아니다.
- 5ft 격자에서 단일 몬스터 표식은 여러 개체를 대표한다. 대형 몬스터의 실제 점유 크기와 통로 통과 가능성을 보장하지 않는다. 함정이 "보스 행동과 연동된다"는 설명과 실제 턴 실행기도 구별해야 한다.
- NPC의 소속 마을이 없어져도 편집 내용을 보존하는 정책은 타당하다. 다만 삭제 국가·이전된 도시·없어진 총본산·이전 보물 소유자의 처리 정책을 통일하고, 고아 참조·보존 기록 목록을 제공해야 한다.
- 보물·종교 동기화는 생성과 누락 보완 중심이다. 면적·역사·소속 변경 때 자동 갱신할 값, 사용자가 고정한 값, 역사 기록으로 보존할 값을 구분한다.
- 근거: [내부 지도 조작 범위](../../src/controllers/dungeon-interior.ts#L102), [관계 검증 정책](../../src/services/planet/project-validation.ts#L59), [보물·종교 보완](../../src/generators/realm-heritage.ts#L111).

### P2. 기능별 창보다 선택 대상 중심의 작업 흐름이 필요하다

- 권장 구조: 왼쪽 세계 계층·통합 검색, 중앙 지도, 오른쪽 선택 대상 상세, 상단 프로젝트·저장 상태. 도시를 선택하면 NPC·시설·보물·종교·인근 던전을 같은 문맥에서 이동하도록 한다.
- NPC/보물 상세 저장과 프로젝트 저장을 같은 의미처럼 보이지 않게 한다. 재생성은 변경 미리보기·수정 항목 잠금·되돌리기를 제공한다.
- 개별 토큰 표시 원칙은 유지한다. 강제 그룹화 대신 레이어 필터, 중요도·확대율별 라벨 밀도, 선택 강조, 토큰과 텍스트의 위치 규칙으로 혼잡을 줄인다.
- 모바일은 데스크톱 편집기를 축소하기보다 열기·탐색·검색·메모·백업 우선으로 설계하고, 정밀 지형·구조 편집은 후순위로 둔다.
- 한국어/영어의 UI 문자열과 고유 지명·사용자 메모를 분리한다. DOM 후처리 번역은 레거시 호환용으로 유지하고 신규 기능은 키 기반 문자열 사전을 사용한다.
- 이는 구조상 권고다. 모달 잘림·토큰 간격·색 대비·터치 영역 등은 현재 실제 화면에서 재검증해야 한다.

### P2. 버전 식별·성능·배포와 테스트 운영을 정리해야 한다

- 앱 버전은 1.1.0이지만 문서 제목은 전역 엔진 VERSION 1.135.0을 사용한다. 앱 버전·엔진 버전·저장 스키마·생성 알고리즘 버전을 분리해 About/진단에 표시한다.
- GitHub main에는 단위 테스트가 연결돼 있으나 일부 배포·E2E·버전 워크플로는 master 기준이다. Sites 공개 앱은 별도 명시적 배포 경로다. main 업데이트를 공개 앱 업데이트로 오인하지 않게 배포 커밋과 환경을 표시한다.
- 현재 빌드 메인 청크는 약 1,160KB/gzip 375KB, RPG 에셋 모듈은 약 1,871KB/gzip 1,406KB다. 실제 초기 로드 시간은 측정하지 않았지만 모바일 비용의 후보임은 확인된다. 이미지의 정적 URL·선택적 로딩과 무거운 참고 데이터 지연 로딩을 검토한다.
- `Campaign.get()`이 읽기만 하는 것이 아니라 전체 스냅샷·동기화·그리기를 실행한다. 자동 저장과 잦은 UI 갱신에 반복 비용과 숨은 부작용이 생길 수 있다. 조회, 변경 명령, 동기화, 렌더링을 점진적으로 분리한다.
- 최초 전체 테스트에서 기존 정착지 테스트가 5초 제한을 초과했다. 단독 실행과 동일 설정 전체 재실행은 통과했다. 제한 시간만 늘리지 말고 import·fixture·자원 경쟁을 프로파일링하고 대형 시드·저장 왕복을 별도 통합 검사로 관리한다.
- 근거: [제목 버전](../../src/services/ui-language.ts#L114), [읽기 시 refresh](../../src/controllers/campaign-world.ts#L720), [워크플로](../../.github/workflows), [배포 기록](../04-report/public-deployment.report.md).

### 2순위: GM 작업대 v1.2

- 통합 검색·세계 계층·선택 상세 패널, 지도↔목록 상호 이동, 위치 북마크.

- 던전의 방/통로/문/함정/보상·몬스터 수동 편집, 되돌리기·다시 실행·항목 잠금.
- GM/플레이어 출력 프리셋과 PNG/SVG·격자·축척·숨김 정보 검사.
- 완료 기준: 도시 선택→NPC 수정→인근 던전 조정→플레이어 지도 출력→프로젝트 복구를 외부 도구 없이 끝낼 수 있다.

### 3순위: 살아 있는 세계관 v1.3

- NPC·세력·종교·보물·장소·던전을 안정적인 ID로 연결하고 소유자·현재 위치·상태를 구분한다.
- 퀘스트를 단순 문장 대신 의뢰인·대상·목적지·조건·보상·세계 변화로 저장한다. 예: 도시 수호 성물 도난→교단 의뢰→인근 언데드 던전→보스와 관련된 NPC→귀환 후 종교/보물 상태 갱신.
- 세션 일지·사건·달력·재방문 상태를 제공한다. 도시/마을 시설 지도와 건물·동굴 구조는 일관된 어댑터·시드·라이선스 정책으로 통합한다.
- 생성 자료는 편집 가능한 초안으로 제공하고, 기존 고정 설정을 자동으로 덮어쓰지 않는다.
