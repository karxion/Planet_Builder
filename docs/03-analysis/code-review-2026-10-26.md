검토일: 2026-10-26. 기준 GitHub 커밋: `82bb5f9630ac1c96a53182ce9fdde60c6837b07b`.

## 총평

행성·정착지·NPC·아이템·던전을 연결하는 GM 제작 도구로서 기능적 기반은 충분하다. 다만 레거시 FMG 편집기와 신규 편집기의 입력 검증·저장·다국어 처리 방식이 다르고, GitHub 작업본과 공개판이 별도 소스로 관리된다. 다음 개발 주기는 신규 생성 기능 확대보다 **동일 소스 배포와 데이터 보존**에 집중하는 편이 낫다.

이번 검토는 코드 읽기, 악성 입력 회귀 테스트, 의존성 검사와 실제 브라우저 조작을 결합했다. 전체 침투 테스트나 클라우드 백엔드 인증 심사는 아니다. P1은 보안·데이터 손실 위험이 있어 우선 처리, P2는 신뢰성·유지보수·사용성 개선을 뜻한다.

## 아직 해결하지 않은 중요 사항

### P1: 공개판과 작업본의 단일 소스 배포

이번에 보안상 중요한 경로는 양쪽에 반영했지만 공개판은 여전히 별도 체크아웃이다. 작업본의 중앙 초안 복구·고급 캠페인 기능 등은 공개판에 전부 존재하지 않는다. 수동 파일 복사는 재발 원인이다.

- 다음 작업: GitHub의 하나의 커밋에서 공개 아카이브를 생성하고 배포한다. 공개판 전용 호스팅 설정만 분리한다.
- 완료 기준: About에 앱 버전·커밋·스키마 버전 표시, CI에서 배포 커밋·테스트 커밋 일치 검사, 이전 버전 롤백 가능.

### P1: 아이템 미저장 초안의 복구 누락

`src/controllers/world-items.ts:31`의 초안은 메모리 Map이다. `beforeunload` 경고는 있지만 지도 생성·불러오기 및 세계 전환 시 비워진다(113·157행). 중앙 `EditorDrafts`/복구 저장 대상에 아이템이 통합되지 않았다. 새로고침 경고만으로 브라우저 종료·충돌·앱 내부 지도 전환을 보호할 수 없다.

- 다음 작업: 아이템도 프로젝트별 초안 저장소·전환 가드·복구 UI에 연결한다. 기존 NPC·설정 편집기와 동일한 규약을 사용한다.
- 완료 기준: 수정 중 새 지도/열기/복구/재시작 후 초안 유지, 다른 프로젝트로의 초안 혼입 없음, 적용·폐기 구분, 내보내기에서 미적용 초안 명시.

### P1: 클라우드 동시 저장의 원자적 충돌 방지

`src/services/planet/bkend-repository.ts:210`에서 revision을 확인한 뒤 업로드와 PATCH(265행)를 별개로 수행한다. 두 PC가 같은 revision을 읽고 각각 저장하면 둘 다 검사를 통과할 수 있다. 현재 프런트엔드 검사만으로 덮어쓰기를 완전히 막을 수 없다.

- 다음 작업: 백엔드가 지원하는 트랜잭션/CAS 또는 ETag 기반 조건부 갱신을 설계한다. 지원 여부를 확인하지 않은 헤더를 임의 추가하지 않는다.
- 완료 기준: 두 클라이언트 동시 저장 중 정확히 하나만 성공, 다른 쪽은 로컬본·서버본·별도 복사 선택, 실패 업로드 정리, 메타데이터/파일 참조 일관성.

### P2: 가져오기 트랜잭션과 운영 보안

- SVG·노트는 세계를 변경하기 전에 검증하지만 `.map`의 더 깊은 구조를 읽는 과정은 여전히 순차적으로 전역 상태를 변경한다. 모든 데이터를 임시 모델에 파싱·검증한 후 한 번에 반영하거나 기존 스냅샷으로 복구해야 한다.
- 소유자 전용 RLS·private 파일 스토리지 설정은 문서만으로 확인할 수 없다. 실제 서로 다른 두 계정의 목록·파일 URL·삭제·만료 토큰 접근 차단 테스트가 필요하다. 이번에는 실제 인증 백엔드를 테스트하지 않았다.
- 공개 URL의 응답에서 CSP·CSP Report-Only·X-Content-Type-Options·Referrer-Policy·HSTS·X-Frame-Options를 확인하지 못했다. CSP는 외부 스크립트와 레거시 인라인 코드를 조사한 뒤 Report-Only부터 단계적으로 적용한다. 이것만으로 현재 악용이 입증된 것은 아니다.
- 다른 레거시 `innerHTML`/jQuery HTML 경로가 남아 있으므로 이번 수정 범위를 전체 XSS 제거로 해석하면 안 된다.
- 외교 관계의 도메인 규칙도 한곳으로 합쳐야 한다. 레거시 `diplomacy-editor.js:332`는 관계를 직접 대입해 신규 국경 편집기의 순환 종속·복수 종주국 검증을 우회할 수 있다. 기록 편집(460행)은 삭제 후 숫자 인덱스를 재배정하지 않아 다음 줄 편집이 잘못된 항목에 적용될 위험도 있다. 이번에는 보안 출력 경계를 수정했으며 이 두 동작은 별도 회귀 테스트와 공통 명령 처리로 해결해야 한다.
- 외부 TinyMCE 로딩 실패를 브라우저에서 관찰했다. 검증된 로컬 에디터 또는 기본 편집기로 전환해 오프라인 동작을 보장한다.

## 추가 기능 제안

1. **캠페인 연결 장부**: NPC → 소유 아이템 → 거주 도시 → 관련 던전 → 국가 관계를 양방향으로 탐색하고 소유권 이동·사망·파괴·관계 변화를 기록한다. 현재 개별 생성물을 실제 세션 자료로 연결하는 효과가 가장 크다.
2. **GM/플레이어 공개 범위**: 숨은 방·함정·보상·NPC 비밀을 객체별로 구분하고 플레이어용 지도·아이템 카드·도시 안내서를 출력한다. 기존 데이터 출력의 비밀 제외 정책을 재사용한다.
3. **파티 기준 조우 설계기**: 인원·레벨·회복 상태·행동 경제와 판본별 XP 예산을 함께 반영한다. 던전 CR 하나만으로 난이도를 확정하지 않으며 일반/도전/헬조선의 변경 근거를 보여준다.
4. **장비·조율·충전 관리**: 유니크 추가 특성을 실제 장비 슬롯·조율 제한·사용 횟수·회복 조건에 연결한다. SRD 원본과 앱 창작 능력을 명확히 구분하고 수동 재정의를 허용한다.
5. **VTT용 출력**: 전투 지도 PNG/WebP, 격자 크기·실제 거리·문/벽/조명/토큰 좌표를 함께 출력한다. Foundry/Roll20 등은 공통 데이터 포맷을 만든 뒤 어댑터로 지원한다.
6. **세계 사건·모험 훅**: 국가 관계와 종교·보물·NPC 목표를 이용해 사건을 생성하되, 자동 생성 결과는 승인 전 초안으로 남긴다. 기존 세계관을 예고 없이 변경하지 않는다.

권장 실행 순서: 단일 소스 배포 → 초안 복구 통합 → 서버 충돌 방지·RLS 실검증 → 가져오기 트랜잭션 → 다국어·레이아웃 → 성능 → 캠페인 장부 → 조우·VTT.

## 외부 라이브러리 근거

기존 jQuery 3.1.1은 공식 보안 권고의 영향 범위에 속한다: [htmlPrefilter XSS](https://github.com/jquery/jquery/security/advisories/GHSA-gxr4-xjj5-5px2), [option HTML 처리 XSS](https://github.com/jquery/jquery/security/advisories/GHSA-jpcq-cgw6-v4j6). 라이브러리 교체 외에도 애플리케이션 입력 정화가 필요하다.

UI 1.12.1은 [공식 Datepicker 보안 권고](https://github.com/jquery/jquery-ui/security/advisories/GHSA-j7qv-pgf6-hvh4)보다 오래된 버전이다. 다만 기존 커스텀 빌드의 해당 위젯 사용 여부와 앱별 악용 경로는 입증하지 않았으며 버전 교체·회귀 검증을 수행했다. 배포물은 [공식 jQuery 릴리스](https://releases.jquery.com/jquery/)와 [공식 UI 릴리스](https://releases.jquery.com/ui/)에서 가져왔고, `public/libs/vendor-manifest.json`에 원본 URL·해시·MIT 라이선스를 기록했다.
