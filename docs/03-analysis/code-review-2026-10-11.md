# 판타지 행성 빌더 코드 리뷰 및 리팩토링

검토일: 2026-10-11. 보안 수정 및 재검증: 2026-10-12.

## 검토 범위

신규 행성 프로젝트의 저장·복구·가져오기, 클라우드 인증·저장, 2D/3D 전환과 비동기 텍스처 갱신을 우선 검토했다. 기존 지형·자원·정착지 표현과 행정 체계의 동작을 유지하는 범위에서 수정했다. 모든 레거시 코드에 대한 보안 감사나 모든 UI 흐름의 검증을 완료했다는 의미는 아니다.

## 남은 주요 발견 사항

### [P1] 여러 기기의 동시 클라우드 저장은 원자적이지 않음

- 위치: `src/services/planet/bkend-repository.ts:209`, `src/services/planet/bkend-repository.ts:261`
- revision 조회 후 별도 PATCH를 수행하므로 두 클라이언트가 같은 revision을 조회한 뒤 모두 갱신할 수 있다. 한 브라우저 안의 저장 직렬화는 이 경쟁을 해결하지 않는다.
- 필요 조치: 서버에서 예상 revision을 조건으로 갱신하는 CAS/트랜잭션을 제공하고 충돌 응답을 정의해야 한다. 확인되지 않은 bkend API를 추측하여 추가하지 않았다.
- 소유자 RLS, 비공개 파일 권한, 실제 업로드 제한과 만료 URL 처리는 배포된 백엔드가 없어 통합 검증하지 못했다.
- 확신도: 높음. 현재 클라이언트 요청은 조건부 갱신이 아니다.

### [P2] 레거시 직접 로더의 복구 한계

- 위치: `src/services/io/load.ts:165`, `src/services/io/load.ts:246`
- FPB 화면의 파일 가져오기는 압축 전후 128 MiB 제한을 적용하지만 기존 FMG 메뉴에서 직접 호출하는 로더의 압축 해제에는 같은 제한이 없다.
- 기존 로더는 전역 월드와 DOM을 단계적으로 변경한다. 중간 실패 시 완전한 이전 상태 복원은 보장되지 않는다.
- 이번 수정에서는 불러오기 실패가 정상 자동 저장본까지 덮어쓰는 것을 막았다. 전체 로더의 파싱/검증/커밋 분리는 후속 작업으로 남겼다.

## 리팩토링 구조

- `project-session.ts`: 문서 유효 범위와 독립적인 로컬/클라우드 저장 큐.
- `project-validation.ts`: 파일 형식과 도메인 설정의 검증.
- `project-codec.ts`: 공통 제한 스트림 읽기, FPB 및 기존 지도 디코딩.
- `cloud-project-row.ts`: 클라우드 목록의 안전한 표시.
- `content-sanitizer.ts`: 지도 SVG, 자원 정의, 노트 HTML의 공통 DOMPurify 정책과 입력 검증.
- `view-3d.ts`: 렌더러 생성/해제 순서를 소유하고 오래된 전환을 무효화.
- 테스트 환경의 `Node` 스텁을 생성자 형태로 바로잡아 Vitest의 `instanceof` 기반 검사가 동작하도록 수정.

## 2026-10-12 보안 수정

- 사용자 승인 후 프로덕션 의존성 `dompurify@3.4.16`을 고정 버전으로 추가했다. 실제 DOM 정화 테스트용 `jsdom`과 타입은 개발 의존성으로만 추가했다.
- `.map`과 `.fpb`가 공유하는 로더에서 지도 SVG, 추가 자원 정의, 노트를 먼저 검증한다. 지도와 정의는 정화된 DOM 노드로 삽입하며 HTML 문자열로 다시 파싱하지 않는다.
- SVG의 스크립트, 이벤트 속성, `foreignObject`, SMIL, 전역 스타일 및 링크 요소를 제거한다. FMG에 필요한 로컬 `use` 참조와 필터는 유지하되 외부 `use` 참조는 차단한다.
- 노트 미리보기, 편집기 전환, 편집 내용 저장, AI 결과 반영에도 동일한 HTML 정책을 적용했다. 기존 서비스 워커의 스크립트 캐시를 고려하여 변경된 레거시 스크립트 URL 버전을 갱신했다.
- 실제 지도 템플릿의 요소 ID와 필터 보존, 한글 라벨·래스터 토큰·로컬 참조 보존, 악성 속성 제거, 잘못된 입력이 기존 지도와 노트를 교체하기 전에 거부되는 경우 등 보안 회귀 테스트 24개를 추가했다.
- DOMPurify의 [공식 문서](https://github.com/cure53/DOMPurify)를 기준으로 정책을 구성했고 배포물에 `public/legal/DOMPurify-LICENSE.txt`를 포함했다.
- 범위 한계: 일반 HTTP(S) 이미지와 인라인 스타일은 허용된다. 전체 레거시 메타데이터의 모든 HTML 삽입 경로를 감사한 것은 아니며, 외부 콘텐츠 전체를 차단하는 정책도 아니다. 사용자 정의 전역 SVG 스타일 제거에 따른 실제 화면 호환성은 브라우저에서 추가 확인해야 한다.

## 검증

- Vitest: 40개 파일, 484개 테스트 통과.
- TypeScript: `tsc --noEmit` 통과.
- 변경 TypeScript 파일: Biome 검사 통과.
- 변경 레거시 JavaScript 파일 2개: `node --check` 통과.
- `npm audit --omit=dev`: 알려진 취약점 0개. 이는 전체 앱의 보안 보증을 의미하지 않는다.
- Vite 프로덕션 빌드 통과. 기존 classic script/CSS 경고와 외부 outDir 경고는 남아 있다.
- 초기 전체 테스트 실행에서 기존 생성기 테스트 2개가 5초 제한을 초과했다. 같은 설정으로 재실행한 전체 테스트가 통과했으며 제한 시간을 늘리거나 테스트를 제외하지 않았다.
- Playwright E2E는 저장소 지침에 따라 자동 실행하지 않았다.
- 로컬 브라우저 직접 확인을 시도했으나 브라우저 도구의 URL 접근 정책으로 차단됐다. 이번 3D 변경의 실제 GPU 렌더링/화면 검증은 미완료다.
- 실제 bkend 인증/파일 저장, 여러 사용자 간 접근 차단, 여러 기기 동시 저장은 미검증이다. 인증/저장 회귀 테스트는 모킹 기반이다.

## 후속 우선순위

1. 정화된 기존 지도·자원 토큰·노트의 실제 브라우저 호환성 확인과 나머지 레거시 메타데이터 HTML 표시 경로 감사.
2. bkend 서버 CAS와 RLS 구성, 실제 계정 2개/브라우저 2개로 통합 테스트.
3. 실제 화면에서 2D→3D→2D 빠른 전환, FPB 복구, 고밀도 지도 편집을 확인.
4. 레거시 지도 로더의 제한된 파싱과 실패 시 복구 설계.

변경은 로컬 작업본에만 반영했다. GitHub 커밋/푸시와 공개 사이트 재배포는 수행하지 않았다. 기존 미추적 QA 이미지도 변경하지 않았다.
