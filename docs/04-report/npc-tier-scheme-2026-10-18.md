# NPC 티어 기준 정정

작성일: 2026-10-18

## 확정 기준

사용자 정정에 따라 앱 전용 티어를 1티어 1~4, 2티어 5~8, 3티어 9~12, 4티어 13~16, 5티어 17~20, 에픽 21 이상으로 변경했다. 이전 NPC 성장 보고서의 티어 범위를 대체하며 공식 D&D 티어를 뜻하지 않는다.

사용자 후속 답변대로 자동 배치는 마을 1티어·도시 2티어·국가 3티어·대륙 4티어를 유지한다. 5티어와 에픽은 자동 생성·재생성하지 않고 NPC 상세에서 직접 지정한다. 기존 레벨·이름·메모·수정 여부는 그대로 보존하며 티어만 새 기준으로 계산한다.

## 반영 내용

- 생성 범위, 목록·상세 표시 및 내보내기 티어 구분을 수정했다.
- NPC 편집과 파일 검증에서 21 이상의 서사 레벨을 허용했다. 소수·0 이하·무한대·JavaScript 안전 정수 범위 초과는 거부한다.
- 에픽은 서사 레벨만 기록한다. 현재 20레벨까지 제공하는 간이 HP·명중·숙련·주문 DC를 임의로 연장하지 않으며, 화면에서 지원 범위를 표시한다.
- JSON 내보내기에 `tierScheme`과 `narrativeTier`를 추가했다. `.fpb`는 기존 스키마를 유지하며 티어를 레벨에서 계산한다.
- 비모험가의 내부 level=1과 CR 0·1/8·1/4·1/2 정책은 유지했다. CR을 티어나 소수 캐릭터 레벨로 변환하지 않는다.
- 설계 문서, CONTEXT, README 및 규칙 고지를 새 기준으로 정리했다.

## 검증

- 집중 회귀 테스트: 5개 파일, 129개 통과.
- 전체 Vitest: 48개 파일, 613개 통과.
- TypeScript `--noEmit`: 통과.
- 변경 TypeScript Biome 검사: 통과.
- Vite 프로덕션 빌드: 통과. 기존 레거시 script/public CSS 및 대형 청크 경고는 유지된다.
- 티어 경계, 20→21레벨, 잘못된 레벨 거부, 5티어·에픽 수동 편집·복구, 자동 생성 상한, 기존 레벨 보존, `.fpb` 왕복, 커머너 CR 분리를 확인했다.
- UI 검증은 jsdom 상호작용 테스트이다. 실제 화면·모바일 및 Playwright E2E는 수행하지 않았다.

로컬 코드와 빌드만 반영했다. GitHub push 및 공개 사이트 재배포는 하지 않았다.
