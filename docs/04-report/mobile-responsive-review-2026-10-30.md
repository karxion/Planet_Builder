# 모바일 회전·해상도 추가 점검

검토 기준 `b5b31978`. 기본 지도의 화면 맞춤 외에 던전 편집, 짧은 화면, 표시 영역 변화와 한·영 메뉴를 점검해 다음 문제를 보완했다.

| 발견한 문제 | 수정 |
| --- | --- |
| 844px 휴대폰 가로 화면과 768~820px 태블릿에서 던전 3열이 유지되어 지도 폭이 214~294px로 줄어듦 | 1024px 이하 또는 높이 600px 이하의 터치 화면에서는 층/지도/속성 탭 사용 |
| 가로 화면 또는 세로로 긴 지도가 폭 기준으로만 맞춰져 지도의 일부가 잘림 | 현재 프레임의 가로·세로 모두에 비율을 유지해 맞춤. 확대 배율은 별도 유지 |
| 확대 시 편집창 전체가 교체되어 스크롤이 70→0px로 초기화 | 기존 SVG와 폼을 유지하고 표시 크기만 변경. 지도 중심을 기준으로 확대하고 회전에도 같은 위치 유지 |
| 탭/확대에서 미적용 부품 입력과 포커스를 잃을 수 있음 | 탭을 표시 속성으로 전환하고 확대 시 폼을 교체하지 않음 |
| 표시 영역이 줄 때 하단 메뉴·확대 버튼·던전 창이 기존 화면 높이를 기준으로 배치됨 | 표시 가능한 높이와 하단 가려진 영역을 공유. 짧은 지도에서는 확대 버튼을 가로로 배치 |
| 작은 PNG 부품의 투명 부분에서 클릭이 방으로 전달됨 | GM용 점유 사각형 클릭 영역과 방별 ‘부품·장치 선택’ 목록 추가. 플레이어 출력에는 클릭 영역 제외 |
| 영문 320px 화면에서 More views 오른쪽이 348px까지 넘어감 | 작은 화면의 긴 보기 모드 이름을 줄바꿈. 수정 후 모든 버튼이 314px 안에 들어옴 |

터치 환경의 상단 작업·보기 모드·언어 선택 영역은 44px 이상으로 보완했다. 신규 생성/복제 설정을 층 목록으로 옮겨 지도 탭의 공간을 확보하고, 저장 호환 안내는 v2 최초 생성/변환 미리보기에서 표시한다.

## 검증

Chromium 터치 에뮬레이션(DPR 3)에서 아래 가용 영역을 사용했다. 실제 기기 수가 아닌 CSS 픽셀의 화면 크기다.

`320×568`, `568×320`, `360×640`, `640×360`, `390×844`, `844×390`, `760×500`, `761×500`, `768×1024`, `1024×768`, `820×1180`, `1180×820`, `1440×900`.

- 기본 지도/헤더의 가로 넘침과 던전 창의 가로 넘침 없음. 각 크기에서 기본 배율의 던전 SVG가 프레임 안에 들어옴.
- 한·영 UI는 320/390px 세로와 568/844px 가로에서 보기 모드 버튼이 모두 화면 안에 있음.
- 확대 전후 가로/세로 중심의 정규화 좌표 차이는 약 0.0003 이하, 회전 후 차이는 약 0.0007 이하로 유지됨.
- SVG/폼 DOM을 유지하고 미적용 개별 부품 입력값이 탭/확대 후에도 남음을 확인함.
- 축소된 `visualViewport.height=400` 이벤트를 모의한 점검에서 지도 하단 400px, 확대 버튼 하단 332px, 보기 메뉴 하단 388px, 던전 창 하단 400px로 모두 표시 영역 안에 있음. 이 점검은 실제 OS 키보드 조작을 대체하지 않음.
- 8×96칸의 세로 지도 전체가 화면 맞춤에 들어오며, PNG는 250×3000px로 출력됨. 화면 표시 크기가 원본 출력 크기/3000px 상한을 바꾸지 않음.
- 확대/회전 전후 저장된 던전 전체 JSON, 세계 크기와 원본 grid 높이가 동일함.
- 관련 Vitest 10개 파일 77개 테스트 통과. 이후 표시 영역 캐시 보완은 관련 4개 파일 22개 테스트로 재확인. TypeScript/Vite 빌드 및 변경 TS 파일 Biome 검사 통과.
- 저장소의 Playwright E2E 모음은 실행하지 않고 별도 브라우저 재현 스크립트로 점검함.
