# 보안 개선 1단계: 프로덕션 정화 라이브러리 패치

## 목적 및 범위

- 2026-10-25 제품 평가에서 확인한 프로덕션 DOMPurify 의존성 경고부터 대응했다.
- `dompurify@3.4.16`을 공식 패치 버전 `3.4.17`로 고정하고 잠금 파일을 동기화했다. 설치는 `npm install --ignore-scripts --no-fund`로 수행했으며 변경된 패키지는 DOMPurify 하나다.
- 새 프로덕션 의존성을 추가하지 않았다. 앱 버전·지도 스키마·SVG/노트 정책·월드 데이터는 변경하지 않았다. 실행 중인 사이트의 배포본이 자동 갱신되는 작업은 아니다.

## 공지와 현재 앱의 조건 구분

| 공지 | 문제 조건 | 기존 앱 경로 |
| --- | --- | --- |
| GHSA-cg2g-xh64-v4q7 | SAFE_FOR_TEMPLATES, 특정 DOM 반환 모드, attached shadow root, 후속 템플릿 평가 | SAFE_FOR_TEMPLATES나 후속 템플릿 평가를 활성화하지 않음 |
| GHSA-mrv2-3pqr-j5jr | IN_PLACE에서 훅이 부모·형제를 제거해 방문되지 않은 노드의 이벤트 속성이 남음 | 문자열을 받아 정화하며 IN_PLACE를 활성화하지 않음 |
| GHSA-c6gr-qvv4-5v3f | XHTML 파서에서 허용된 SMIL의 attributeName 대소문자 처리 | XHTML 파서 모드를 쓰지 않으며 해당 SVG 애니메이션 태그를 금지함 |

버전이 공지 범위에 포함된 사실과 실제 앱에서 공격이 성립한다는 주장은 다르다. 이번 작업에서 기존 앱의 공격 실행을 재현했다고 보고하지 않는다. 사용하지 않는 옵션을 새로 활성화하지 않고 라이브러리 자체를 패치했다.

## 추가한 검증

- 새 테스트: `src/services/dompurify-security.test.ts`.
- attached shadow root 안에서 문자 사이의 금지 요소를 제거한 뒤 조합되는 세 종류의 템플릿 구문 제거: 3개.
- 훅에서 부모 또는 다음 형제를 제거한 경우, 분리된 이미지 참조의 이벤트 속성까지 정화되는지: 2개.
- XHTML의 허용된 SVG 애니메이션에서 href를 다시 지정하는 attributeName 제거: 1개.
- 위 테스트는 별도의 purifier 인스턴스로 패치된 라이브러리의 비기본 모드를 검사한다. 앱의 실제 입력 경로는 기존 지도·노트·가져오기 경계 테스트로 함께 검사한다. 실행 가능한 템플릿 평가나 실제 이벤트 발화 테스트는 하지 않았다.
- 정상 지도 레이어·필터·로컬 use 참조·래스터 자원·한글 라벨·노트 서식 보존, 위험 속성·스크립트 제거, 잘못된 입력 시 기존 지도 유지 테스트를 통과했다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| 정화·보안 대상 테스트 | 3개 파일 / 30개 통과 |
| 전체 단위 테스트 | 54개 파일 / 692개 통과 (`--maxWorkers=2`) |
| TypeScript | `tsc --noEmit` 통과 |
| 변경 및 관련 TypeScript | Biome 검사 통과 |
| 프로덕션 빌드 | 통과; 기존 레거시 스크립트·대형 청크 경고는 유지 |
| 프로덕션 의존성 감사 | 패치 전 critical 1개 → 패치 후 0개 |
| 전체 감사 | 설치 결과 10개 항목(critical 3, high 6, moderate 1), 모두 개발 의존성 범위 |
| 라이선스 | 배포 고지와 설치된 LICENSE의 SHA-256 일치, 변경 불필요 |

감사 결과 0개는 조회 시점에 알려진 프로덕션 의존성 경고가 없다는 뜻이다. 앱 전체 보안, 실제 브라우저 실행 결과 또는 공개 배포 완료를 보증하지 않는다. Playwright E2E는 저장소 지침에 따라 자동 실행하지 않았다.

## 남은 작업

1. 후속 로컬 작업에서 Vite·Vitest 등 개발 도구 경고 10개 항목을 해소하고 전체 테스트·타입 검사·빌드를 재검증했다. 당시 1단계 결과 표의 10개는 과거 기록이며 현재 전체 감사는 0개다. [개발 도구 보안 보고서](dev-tool-security-2026-10-25.md) 참고. 개발/테스트 서버는 외부에 공개하지 않는다.
2. 미확정 편집 초안과 프로젝트 저장 상태를 분리하고 저장·복구 흐름을 개선한다.
3. 검증된 변경을 별도로 GitHub에 반영하고 기존 Sites 사이트에 재배포해야 실제 공개 앱에도 패치가 적용된다. 이번 작업에서는 커밋·업로드·배포를 수행하지 않았다.
