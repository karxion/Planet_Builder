# 저장·복구 안정화 2단계: 초안 영구 보존

## 목표와 범위

1단계의 메모리 전용 초안을 로컬 복구 기록에 보존해 새 실행 세션에서 다시 편집할 수 있게 했다. 확정 월드와 미적용 초안의 의미는 유지하며, 파일·클라우드로 초안을 자동 반출하지 않는다.

대상은 기존에 초안을 추적하는 NPC, 보물, 종교, 건국 연도, 행성 설정 폼이다. 새 프로덕션 의존성이나 FPB 스키마 변경은 없다. 앱 버전·GitHub·공개 사이트도 갱신하지 않았다.

## 저장 구조

- `EditorDraftStore.snapshot()`은 초안 키·원래 값·입력값의 복사본을 만든다. `restore()`는 검증된 초안을 별도 편집 상태로 복원하며 월드 객체에 적용하지 않는다.
- `RecoverySnapshot`에 선택적 `drafts`와 `draftBytes`를 추가했다. 기존 IndexedDB의 같은 기록에 지도 Blob과 초안을 함께 기록하므로 초안만 다른 지도 세대에 붙는 별도 쓰기 간격을 만들지 않는다. DB 버전 변경은 필요하지 않다.
- 초안 형식은 `schemaVersion: 1`, `projectId`, `snapshotId`, `entries`다. 복원 시 기록 소유 ID와 일치해야 하며, 해당 지도의 NPC·보물·종교·국가 또는 행성 설정 키만 허용한다.
- 허용 필드와 문자열 타입·길이, 클래스·능력치 유형·성향 등의 선택값, 중복 키를 검사한다. 비밀번호·인증 폼은 수집하지 않는다. 인증 필드나 `__proto__`·`constructor` 같은 비허용 필드도 거부한다.
- 잘못된 초안은 경고 후 제외하되 정상 지도와 나머지 정상 초안은 복구한다. 삭제된 엔티티 등 현재 지도에 연결할 수 없는 초안을 자동 재배치하거나 자동 적용하지 않는다.
- 초안 없는 이전 복구 기록과 기존 단일 자동 저장도 계속 읽을 수 있다. 파일·클라우드 페이로드는 여전히 확정 데이터만 담는다.

## 저장 주기와 상태

- 실제 초안 revision이 바뀌면 750ms 유휴 저장을 예약한다. 연속 입력으로 유휴 시간이 생기지 않아도 3초마다 보존을 시도한다. 이는 저장 시도 시간이며 느린 직렬화·DB 잠금·할당량 문제까지 포함한 3초 내 완료 보증은 아니다.
- 로컬 월드 revision과 초안 revision을 따로 추적한다. 트랜잭션 완료 후 해당 revision만 보존 완료로 표시한다. 쓰기 중 추가 입력·적용·버리기가 발생하면 최신 상태를 이어서 저장한다.
- 초안만 바뀔 때는 지도 Blob과 현재 복구 ID를 재사용해 지도 직렬화와 과거 세대 소모를 줄인다. 월드 변경 신호가 있으면 새 지도 Blob과 새 복구 세대를 만든다.
- 기존 편집기에서의 포커스·포인터 조작은 지도 캐시를 무효화한다. 복구 중 월드 변경 신호가 발생한 경우에도 기존 Blob을 최신이라고 간주하지 않고 다시 생성한다. 레거시의 모든 변경 감지를 완성한 것은 아니다.
- 새 실행 세션이나 과거 복구본을 연 뒤 처음 수정하면 별도 복구 ID로 분기한다. 이전 기록이나 다른 탭이 읽은 기록을 직접 변경하지 않는다. 여러 탭의 자동 병합·충돌 해결 기능은 아니다.
- 적용 또는 버리기로 초안이 없어졌다는 사실도 빈 목록으로 저장한다. 최신 복구에서 지운 초안이 되살아나지 않도록 한다. 사용자가 과거 세대를 직접 열면 당시 초안이 복원될 수 있다.
- 초안 보존 상태, 실패 상태, 포함 개수를 기존 복구 UI에 표시한다. 월드와 초안이 모두 로컬에 반영됐을 때 종료 경고를 해제한다. 저장 대기·실패 상태에서는 경고를 유지하며 비활성 전환 시 즉시 보존도 시도한다.

## 크기와 안전 경계

- 한 기록당 최대 256개 초안, 허용 필드 값당 최대 4,000자, 직렬화 문자열의 UTF-16 추정 크기 약 4MiB를 제한한다. 브라우저 실제 디스크 할당량을 측정한 값은 아니다.
- 기존 약 100MiB 복구 예산에는 초안의 추정 크기도 포함한다. 단일 최신 지도 자체가 큰 경우의 예외와 브라우저 할당량 실패 정책은 1단계와 같다.
- 저장 실패는 원래 복구 기록을 성공으로 치환하지 않는다. 미보존 초안은 메모리에 유지하고 오류·종료 경고를 표시한다. 적용·정리 또는 FPB 파일 백업으로 대응할 수 있으나 FPB에는 미적용 초안이 포함되지 않는다.
- 저장 시도 전 또는 완료 전 강제 종료하면 마지막 입력은 사라질 수 있다. 저장소 삭제·브라우저 자동 제거·공유 PC 접근·디스크 장애에 대한 독립 백업도 아니다. 같은 브라우저 출처의 로컬 기록이며 기기 간 초안 동기화는 지원하지 않는다.

## 발견해 함께 수정한 점

- 빈 NPC 레벨을 복원해 상세를 다시 열면 티어 검사나 간이 전투 계산이 유효하지 않은 레벨을 받을 수 있었다. 검증되지 않은 progression에는 전투 수치를 표시하지 않고 입력 확인 상태를 보여준다. 빈 원문 입력은 유지하며 월드에 자동 적용하지 않는다.
- 선택적 초안 필드가 빠진 경우 NPC 클래스 등의 값이 문자열 `undefined`로 바뀌지 않도록 확정된 NPC 값을 기본값으로 사용한다. 허용되지 않은 명시적 옵션 값은 복구 검증 단계에서 제외한다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| 전체 Vitest | 58개 파일 / 754개 통과 (`--maxWorkers=2`) |
| 추가 회귀 검사 | 1단계의 724개 대비 30개 추가 |
| TypeScript | `tsc --noEmit` 통과 |
| Biome | 변경 TypeScript 12개 파일 검사 통과 |
| 프로덕션 빌드 | 통과, 기존 레거시 스크립트·대형 청크 경고 유지 |
| 새 프로덕션 의존성 | 없음 |
| 실제 브라우저·모바일·IndexedDB 엔진 | 미검증 |
| Playwright E2E | 저장소 지침에 따라 자동 실행하지 않음 |
| GitHub 업로드·공개 재배포 | 미실행 |

검사 범위는 ID·스키마·필드·옵션·크기 제한, 새 편집 세션 복원, 빈 숫자 값, 메모리 복사 격리, 적용·삭제와 지연 쓰기, 프로젝트 분리, 재실행 후 분기, 연속 입력의 저장 시도, 실패 시 경고, Blob 재사용·무효화, 지도·초안의 동일 트랜잭션 기록 및 파일 페이로드 분리를 포함한다.

재실행 검사는 jsdom에서 앱 모듈·편집 상태를 새로 초기화하는 방식이다. 저장소 검사는 기존 트랜잭션 이벤트 모형을 사용했다. 실제 브라우저 창 종료나 실제 IndexedDB 엔진을 실행한 증거가 아니며, 화면·터치·모바일 강제 종료도 검증하지 않았다. 이전 접근 제한을 우회해 브라우저나 개발 서버를 실행하지 않았다.

## 후속 순서

1. 실제 브라우저에서 입력→보존→새로고침→복구→적용/버리기→재복구를 확인하고, 용량 실패·여러 탭·긴 한글 텍스트·모바일 화면을 검사한다.
2. 레거시 편집기와 지도 교체 경로의 확정 변경 이벤트·초안 정책을 점진적으로 통일한다. 읽기 시 월드 동기화가 일어나는 구조도 계속 분리해야 한다.
3. 클라우드의 서버 측 원자적 revision 갱신은 별도 과제로 유지한다. 다음 독립 알고리즘 개선 후보는 던전 난이도 변경의 난수 스트림 분리다.
