# 지저 지역지도 구현 결과

## 구현

- 3개 깊이 층(얕은 지저/중층/심층), 시드 및 공동 밀도 12/24/36개.
- 불규칙 공동·건조 터널·호수·용암, 거주지/창작 세력과 공동 바닥으로 제한된 세력권.
- 현재 지상 도시에서 분산된 최대 4개 출입구와 인접 깊이 층을 잇는 통로.
- 현재 층 장소 편집, 지형 붓, 같은 좌표 체계에서 공간/층간 이동.
- 수동/편집된/편집 중인 장소를 보존하는 명시적 지저 재생성.
- FPB/복구/Drive 공통 프로젝트 저장 구조에 지형 포함. 현재 층의 독립 SVG/최대 3000px PNG 출력.

사용법과 재생성 범위는 [설계 문서](../02-design/underground-map-v1.md)에 정리했다. 지저 지역지도 단계이며 공동 내부 전투지도와 도시 조감도 자동 배치는 포함하지 않는다.

## 검증

- `npx vitest run src/generators/underground.test.ts src/services/world-spaces/model.test.ts src/renderers/world-spaces.test.ts src/services/planet/map-load-lifecycle.test.ts`: 4개 파일, 36개 테스트 통과.
- 생성 재현성·격자 크기/범위·기존 데이터 불변성, 3개 밀도에서 거주지/입구의 건조 연결, 수동 장소/수정된 장소/세력/수동 연결 보존, 압축 FPB 지형/활성 층 복원, 잘못된 지형 거부, 층별 브러시 적용을 검증했다.
- 변경 TypeScript 11개 파일의 Biome 검사 및 `npm run build` 통과. 기존 레거시 스크립트·번들 크기 경고는 유지된다. 저장소 전체 린트의 기존 오류와 전체 테스트의 기존 파일 크기 경계 테스트는 이번 범위에서 다시 실행하거나 수정하지 않았다.
- 실제 Chromium 수동 점검: 시드/밀도 생성, 3개 깊이 전환, 층간 화살표 이동, 물 붓 편집, 현재 깊이 도시 추가, SVG/3000px PNG 출력, FPB 저장·재열기 시 지형 동일, 지상 payload에서 지저 SVG 제외, 수동/수정된/초안 작성 중 장소의 지저 재생성 보존, 지상 새 지도 후 지저 지형 보존, 390px 모바일 편집창을 확인했다. 앱 예외는 관측되지 않았다.
- 실제 계정의 Google Drive 업로드/불러오기는 수행하지 않았다. 지형은 별도 Drive 저장 구현 대신 기존 공통 프로젝트 코덱을 통해 저장된다.
