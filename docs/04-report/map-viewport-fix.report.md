# 지도 화면 맞춤 오류 수정

## 원인

- 화면 크기 변경 시 SVG 영역과 확대 범위만 갱신하고 실제 지도 변환에는 새 배율을 적용하지 않았다.
- 불러온 지도의 원래 크기가 719×764인 상태에서 화면이 1440px 이상으로 커져도 지도는 왼쪽에 원래 크기로 남았다.
- 화면 높이 계산이 행성 빌더의 상단 도구 모음 높이를 고려하지 않았다.
- 확대 초기화가 화면 맞춤 대신 배율 1을 적용했다.

## 수정

- 월드 데이터 크기와 출력 뷰포트 크기를 분리했다. 화면 크기 변경으로 생성 설정이나 셀 좌표를 변경하지 않는다.
- 지도 출력 영역은 현재 창 너비와 상단 도구 모음을 제외한 높이를 사용한다.
- 원본 가로·세로 비율을 유지하면서 빈 영역 없이 화면을 채우는 배율과 중심을 적용한다. 화면과 지도 비율이 다르면 화면 밖 부분은 이동해서 볼 수 있다.
- 기본 화면에서는 창 크기에 맞춰 다시 맞추고, 확대 중에는 현재 위치와 배율을 가능한 범위에서 유지한다.
- 확대 초기화, 기본 확대 범위 복원, 국가·마을 위치 이동에도 올바른 배율과 이동 경계를 적용한다.
- 생성·불러오기 시에는 중앙으로 맞춘 뒤 위치 링크의 이동을 처리한다. 2D 복귀 시 화면 맞춤을 위치 이동보다 먼저 수행한다.

## 실제 브라우저 검증

- 1440×900: 지도 출력 1440×842, 상단 높이 58px. 배율 약 2.00278로 화면 전체를 채움.
- 1920×1080: 지도 출력 1920×1022. 배율 약 2.67038로 화면 전체를 채움.
- 390×844: 지도 출력 390×744, 상단 높이 100px. 가로·세로 비율 유지 및 빈 영역 없음.
- 마을로 이동해 6배 확대 후 1440→1920 변경: 배율 6과 중심 좌표 (173.02, 274.89) 유지.
- 확대 초기화 후 중앙 화면 맞춤 확인.
- 모바일 3D 전환 및 데스크톱 크기로 변경 후 2D 복귀 확인.
- 새로고침과 자동 저장본 복구 후 화면 맞춤 확인.
- 원본 지도 크기 719×764, 국가 경로 44개, 강 경로 197개, 이름표 862개 유지 확인. 지도 재생성이나 NPC 수정은 수행하지 않았다.

## 테스트

- 타입 검사 통과.
- Vitest 17개 파일, 187개 테스트 통과. 화면 맞춤 계산 회귀 테스트 6개 추가.
- 프로덕션 빌드 통과. 기존 레거시 스크립트와 청크 크기 경고는 유지된다.
- `tests/e2e/planet-viewport.spec.ts`에 실제 지도 영역, 리사이즈, 마을 확대, 초기화 회귀 검사를 추가했다. 저장소 지침에 따라 E2E 러너는 자동 실행하지 않았으며, 위 실제 브라우저 검증을 수행했다.
