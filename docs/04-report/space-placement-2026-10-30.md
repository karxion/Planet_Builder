# 공동세계 출입구·해저 도시 자동 배치 조정

## 변경

- 공동세계의 일반 출입구는 지상 도시 좌표를 복사하지 않고 주변의 독립된 실제 지점을 선택한다. 전달된 모든 지상 도시와 보존된 지상/지저 도시에서 정규화 거리 0.03 이상 떨어지고, 기준 도시에서 0.18 이내인 후보 중 약 0.055 거리의 지상 육지를 우선한다. 출입구끼리는 0.14 이상 이격한다. 적합한 후보가 없으면 해당 후보를 건너뛴다.
- 지상·공동세계 양쪽의 새 관문은 같은 세계 좌표를 사용한다. 내부 도시 연결 경로도 실제 관문 좌표에서 시작한다. 표시용 아이콘 이동은 사용하지 않는다. 극지 관문은 85° 위도를 유지하며 도시와 충돌하면 같은 위도의 다른 경도를 선택한다. 새 내부 도시도 극지 관문 후보를 피한다.
- 해저 수도 및 일반 도시의 자동 배치 후보는 사방 8%를 제외한 바닷속 셀로 제한한다. 외곽 바다는 세력권 성장과 교역로 탐색에 계속 참여한다. 안쪽 바다가 부족하면 도시 수를 줄이고, 외곽으로 되돌아가 배치하지 않는다.
- 생성 UI에 배치 규칙과 기존 지도 적용 방법을 한국어/영어로 안내한다. 저장 스키마와 앱 버전은 변경하지 않는다.

## 저장 데이터와 적용 범위

새로 생성하거나 공간 편집의 해당 지도 ‘다시 생성’을 실행할 때 적용된다. 파일 열기나 복구 시 기존 지도를 자동 이주·재생성하지 않는다. 기존의 명시적 재생성 확인 흐름을 유지하며, 직접 편집한 장소·주민·아이템과 장소 편집 초안을 보호하는 기존 처리도 유지한다. 따라서 사용자가 직접 배치·편집한 외곽 도시는 그 위치에 남을 수 있다. 재생성은 기존 제품 안내대로 자동 장소·경로·지형을 다시 만든다.

## 검증

- 관련 생성기 4파일 45개 테스트 통과: 독립 출입구, 주변 작은 도시 회피, 양쪽 관문 좌표 및 경로 연속성, 극지 위도·편집 보존, 여러 시드의 해저 도시 여백, 안쪽 바다가 없는 지도, 직접 편집한 외곽 도시/주민 보존 포함.
- 전체 단위 테스트 120파일 1,251개 통과 (`--maxWorkers=2`). 해당 프로세스에만 긴 TEMP/TMP 경로를 사용했다. Playwright E2E는 실행하지 않았다.
- `npm run build`의 TypeScript 검사와 Vite 빌드 통과. 기존 레거시 스크립트/CSS 및 청크 크기 경고는 남아 있다.
- 독립 localhost 4193의 실제 브라우저에서 해저 도시 12개, 공동세계 관문 4개, 도시와 떨어진 표시 및 관문 → 지상 이동을 확인했다. 브라우저 콘솔 오류 없음. 사용자 공개 사이트의 작업 중 지도/저장소는 조작하지 않았다.
- 브라우저 증빙: 작업 폴더 `.codex/space-placement/underwater-cities.jpg`, `hollow-gateways.jpg`, `surface-gateway.jpg`.
