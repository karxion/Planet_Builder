# 저장·복구 안정화 1단계

이 문서는 1단계 시점의 기록이다. 이후 초안의 로컬 영구 보존과 새 실행 세션 복원을 구현한 결과는 [2단계 보고서](draft-persistence-2026-10-25.md)에 구분했다. 아래 메모리 전용 설명과 미완료 목록은 당시 기준이다.

## 문제와 범위

평가에서 확인한 핵심 문제는 상세 입력이 확정되지 않았는데도 문서의 change 이벤트가 자동 저장을 예약하고, 확정 데이터만 저장한 뒤 저장 완료를 표시할 수 있다는 점이었다. 상세 렌더링도 선택·검색·필터·탭 이동 때 입력을 잃을 수 있었다.

또한 기존 `ldb` 래퍼는 일부 실패 경로의 reject 처리가 없고 put 성공을 저장 성공으로 취급한다. 이번에는 FPB 복구 경로를 별도 TypeScript 저장소로 이전했다. 기존 `.map` 도구가 사용하는 레거시 래퍼 전체를 변경한 것은 아니다.

새 의존성, 지도 스키마 변경, 앱 버전 변경은 없다. 기존 보안 패치와 사용자 작업 파일을 유지했다. GitHub 업로드·태그·배포는 수행하지 않았다.

## 변경

### 적용 전 초안

- `EditorDraftStore`는 이름이 있는 폼 컨트롤의 원래 값과 현재 값을 별도로 보관한다. 유효하지 않은 숫자 입력의 빈 문자열도 확정 레벨 0과 구분해 유지한다.
- NPC, 보물, 종교, 국가 건국 연도, 행성 설정에 적용했다. 항목별 키를 사용하며 선택·검색·필터·페이지·탭·창 이동 후 같은 항목으로 돌아오면 복원한다.
- 초안 수정은 월드 데이터를 변경하거나 프로젝트 자동 저장을 예약하지 않는다. 상세의 적용 버튼을 눌러 검증에 성공한 경우에만 월드 데이터 변경 이벤트를 보낸다.
- 초안 버리기, 원래 값으로 되돌렸을 때 수정 상태 해제, 폼 재바인딩 시 이전 이벤트 제거를 구현했다. 참고 아이템 선택이 효능 필드를 갱신하거나 취소됐을 때도 실제 최종 값을 추적한다.
- 초안이 남아 있으면 저장 완료 표시 대신 초안 존재를 알린다. 오류 상태는 초안 표시 때문에 숨기지 않는다. 명시적 파일·클라우드 저장 시 초안이 미포함된다는 확인을 받는다.
- 세계 생성 결과, NPC 객체, 보물 객체 등의 직렬화에 초안을 섞지 않는다. 초안은 현재 메모리 세션에만 있으며 새로고침·프로세스 종료 후 영구 복구는 아직 지원하지 않는다.

### 로컬 복구

- 새 IndexedDB `fpb-recovery`의 `snapshots` 저장소를 사용한다. 각 기록은 프로젝트 ID, 복구본 ID, 이름, 저장 시각, 순번, gzip FPB Blob이다.
- 최근 최대 5개 프로젝트, 프로젝트별 최대 3세대, 이전 기록 포함 약 100MiB를 보존한다. 최신 단일 복구본 자체가 예산보다 크면 그 복구본만 보존을 시도한다. 브라우저 할당량이 부족하면 실패할 수 있다.
- 이전 세대 삭제와 신규 기록 추가는 같은 readwrite 트랜잭션으로 수행한다. put 요청 발행이나 성공 이벤트가 아닌 트랜잭션 완료를 성공 기준으로 삼는다. 중단·용량 오류 시 그 트랜잭션의 삭제도 함께 취소된다.
- 순번은 같은 쓰기 트랜잭션 안에서 증가시켜 시스템 시계가 뒤로 바뀌어도 마지막 저장을 식별한다. 프로젝트 데이터의 저장 시각·스키마를 바꾸지는 않는다.
- 상단 기록 아이콘에서 복구 목록을 열고 원하는 세대를 선택할 수 있다. 과거 세대를 열면 같은 로컬 프로젝트의 새 복구 세대로 다시 보존한다.
- 자동 복구 시 최신 프로젝트의 기록만 대상으로 하며 손상된 최신 Blob은 같은 프로젝트의 이전 세대를 시도한다. 무관한 다른 프로젝트로 조용히 넘어가지 않는다.
- 새 복구 기록이 없을 때 기존 `d2/s/lastPlanetProject`를 읽는다. 기존 Blob은 삭제하지 않으며 다음 자동 저장에서 새 저장소로 보존한다. 이전 DB가 없는 경우에는 빈 레거시 DB를 만들어 기존 도구의 스토어 생성을 방해하지 않는다.

### 저장 상태와 교체 경계

- 로컬 복구 완료 revision과 클라우드 반영 revision을 따로 추적한다. 복구 창에 초안 수, 로컬 최신/미반영, 클라우드 미연결/최신/미반영을 구분한다.
- 이전 revision의 비동기 저장이 끝나도 최신 변경을 저장 완료로 표시하지 않는다. 기존 ProjectSession의 문서 세대·채널별 큐도 유지한다.
- 파일 다운로드는 다운로드 요청으로 표기하며 브라우저가 실제 파일 기록을 마쳤다고 보증하지 않는다. 다운로드 성공을 로컬 복구 성공으로 치환하지 않는다.
- 신규 셸의 파일 열기·클라우드 열기·복구본 열기·행성 생성 전에 미반영 작업 교체를 확인한다. 읽기 중 새 프로젝트 변경이나 초안 입력이 생기면 늦은 교체를 중단한다.
- 행성 생성은 확인 후 기존 생성기를 직접 호출해 두 번째 레거시 확인을 취소했는데 설정만 변경되는 흐름을 없앴다. 지형 편집 중에는 해당 요청을 실행하지 않는다.
- 페이지 종료 시 미적용 초안이나 미반영 로컬 변경이 있으면 경고를 요청한다. 페이지 비활성 전환 때 확정 데이터의 즉시 저장도 시도한다. 브라우저·OS 강제 종료나 모바일의 비동기 저장 완료를 보장하지는 않는다.

| 전체 Vitest | 57개 파일 / 724개 통과, `--maxWorkers=2` |
| 신규·보강 검사 | 기존 692개 대비 32개 추가 |

| Biome | 변경 TypeScript 11개 파일 검사 통과 |
| 프로덕션 빌드 | 통과, 기존 레거시 스크립트·대형 청크 경고 유지 |
| 실제 브라우저·모바일·WebGL | 미검증 |
| 실제 브라우저 IndexedDB·할당량·강제 종료 | 미검증 |
| 실제 클라우드 저장·권한·여러 기기 | 미검증 |
| Playwright E2E | 저장소 지침에 따라 자동 실행하지 않음 |

회귀 검사는 초안별 분리·복원·취소·빈 숫자 값, NPC/보물/종교의 실제 DOM 컨트롤 전환, 재바인딩, 지연된 로컬 저장, quota abort, 트랜잭션 완료 전 미완료 상태, 세대 보존·바이트 예산·시계 역행, 기존 Blob 읽기, 손상 복구본의 현재 초안 보호, 복구 읽기 중 새 입력, 재생성 취소·단일 확인, 비활성 전환을 포함한다.

DOM 검사는 jsdom이며 화면 캡처나 실제 클릭 동작의 브라우저 검증이 아니다. 저장소 검사는 트랜잭션 이벤트 모형을 이용했다. 실제 IndexedDB 엔진의 롤백·디스크 영속성·여러 탭 잠금 동작을 재현했다고 주장하지 않는다. 새 개발 서버를 실행하거나 공개 사이트를 갱신하지 않았다.

## 남은 작업

1. 실제 1440×900·1920×1080·390×844 화면에서 긴 한글 이름, 복구 목록 스크롤, 기록 아이콘·초안 취소 버튼 접근성과 창 이동을 확인한다.
2. 실제 IndexedDB에서 저장·새로고침·과거 세대 복구·용량 초과·다른 탭 동시 실행을 검증한다. 브라우저 저장소 삭제·자동 제거를 대비한 FPB 파일 백업은 계속 필요하다.
3. 초안의 프로젝트별 영구 보존과 재실행 복구를 추가한다. 현재 단계는 초안의 세션 내 유지와 명확한 상태 표시에 한정된다.
4. 레거시 편집기·레거시 지도 열기/재생성 경로의 초안 및 교체 경고를 일관되게 확장한다. 아직 모든 FMG 컨트롤을 확정 변경 이벤트로 전환하지 않았으며 지도 pointerup/change 기반 추정 변경도 남아 있다.
5. 클라우드의 원자적 revision 갱신은 서버 지원 확인 후 별도로 구현한다. 이번 클라이언트 상태 구분은 여러 기기의 동시 저장 충돌을 해결하지 않는다.
6. 다음 독립 개선 후보는 던전 난이도 변경의 난수 스트림 분리와 기본 조우 유지다.
