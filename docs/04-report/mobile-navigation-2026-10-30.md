# 모바일 지도 조작 개선

- 휴대폰/터치 기기는 세계 지도를 비율을 유지해 화면에 맞추고, 지도 데이터의 크기와 표시 영역 크기를 분리한다.
- 확대·축소·화면 맞춤을 44px 버튼으로 제공한다. 버튼의 간단한 기호는 외부 아이콘 폰트를 요구하지 않는다.
- 이동 중에는 viewbox 변환만 프레임마다 반영하고, 표식 배치·라벨 크기·좌표·축척·미니맵 갱신은 이동 종료에 합친다. 순수 이동에서 교단·외교 표식의 반복 속성 쓰기도 생략한다.
- 레이아웃 viewport와 visualViewport를 구분해 화면 회전·주소창 높이·화상 키보드에 대응한다. SVG 폭이 회전 후 브라우저 viewport를 다시 확장하지 않게 제한한다. 3D canvas도 같은 표시 영역을 사용한다.
- 터치 이동에서 호버 계산을 생략하고, 조작 중 무거운 SVG 필터를 일시적으로 생략한다. 터치/모션 감소 환경에서 첫 로딩 애니메이션을 단축한다.

검증: 관련 Vitest 9개 파일 67개 테스트 통과, TypeScript/Vite 빌드 성공, 변경 TS 파일 Biome 검사. 저장소의 Playwright E2E 모음은 실행하지 않았다. 별도 Chromium 휴대폰 에뮬레이션에서 버튼·핀치·양축 이동·회전·높이 변경·FPB 저장/재열기·3D 화면 크기를 수동 스크립트로 점검했다.

동일한 시드와 스크립트의 합성 터치 비교에서 표식 전체 재배치 횟수는 17→2회, 최장 프레임 간격은 약 117→33ms였다. 실제 휴대폰 측정이나 보장된 성능 수치가 아니며, 최초 화면 맞춤 배율도 변경되었다. Android/iOS 실기기 검증은 남아 있다.

표시 크기/조작 전후 세계 격자·높이·도시 데이터는 동일하다. FPB 재열기에서 저장 원본 grid 높이/도시/세계 크기는 보존된다. 기존 로더가 reGraph로 재계산하는 pack 높이 일부는 다시 열 때 달라지는 것을 관찰했으며, 이번 모바일 변경에서 해당 저장 알고리즘은 변경하지 않았다. 3D 내보내기 경로의 외부 폰트 fetch는 클라우드 네트워크에서 실패할 수 있어 해당 오류와 표시 크기 검증을 분리했다.
