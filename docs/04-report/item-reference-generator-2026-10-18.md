# 아이템 레퍼런스 생성기 업데이트

작성일: 2026-10-18

## 반영 범위

- 공식 CC BY 4.0 SRD 5.1 (2014) 240개, SRD 5.2.1 (2024) 258개 마법 아이템 항목·계열을 판본별로 색인화했다. 두 판본의 동일 이름은 별도 기록이며 498개의 서로 다른 고유 아이템이라는 뜻은 아니다.
- 제목·분류·희귀도·조율·원문·페이지와 안정적인 원본 ID를 저장한다. PDF의 SHA-256과 예상 항목 수를 고정한 재생성 스크립트를 추가했다.
- 거인 힘, 치유 물약, 주문 스크롤, 아이운 스톤, 경이로운 힘의 조각상, 발할라의 뿔, 수정구, 깃털 토큰, 강화 장비 등의 변동 희귀도·하위형을 구분한다. 모든 색인 항목에 하나 이상의 선택지가 있는지 테스트했다.
- 생성은 국가 성격과 희귀도를 고려한 결정적 가중 추첨이다. 혼합 모드는 판본을 먼저 선택하고 하위형 수에 따른 계열 편향을 완화한다.
- 원본 하나의 효과·행동 비용·충전·제약·저주를 유지하고 이름·서사·RP 상징성을 창작한다. 수치 합산이나 공식 전투 능력치의 자동 재설계는 하지 않는다.
- 새 보물의 이름은 원본 분류에 맞추며, 전체 판본 변경도 장비 분류를 유지한다. 도시 상징품의 유니크는 RP 개념이며 별도 공식 희귀도가 아니다.
- 상세 창에 판본·원본·하위형 선택, 원문, 출처 링크, 원본 효과 유지/GM 수정 효과 구분을 추가했다. 취소 시 직전 선택을 복원하고 전체 판본 변경 시 오래된 상세 편집 내용이 남지 않도록 수정했다.
- 기존 자동 생성 보물에는 원본을 보완하면서 이름·상징성·유래·메모를 보존한다. 수동 편집한 보물은 자동 변경하지 않는다. `.fpb`에 원본 ID·판본·하위형·창작 방식·기본 판본 정책을 저장한다.
- SRD 5.1/5.2.1 출처·수정 범위·CC BY 4.0 고지, README와 설계 문서를 업데이트했다. PDF 입력은 Git 및 배포에서 제외하며 런타임에는 네트워크·Python을 요구하지 않는다.

## 검증 결과

- `node node_modules/vitest/vitest.mjs --run --maxWorkers=2`: 46개 파일, 582개 테스트 통과.
- `node node_modules/typescript/bin/tsc --noEmit`: 통과.
- 변경 TypeScript에 대한 Biome 검사: 통과.
- `node node_modules/vite/bin/vite.js build`: 통과. 기존 레거시 script/public CSS 처리 및 큰 청크 경고는 남아 있다. 메인 JS는 약 1,101 kB, gzip 약 351 kB이며 추후 원문 지연 로딩 검토가 가능하다.
- 판본/희귀도 경계, 명칭 개정, 가변 하위형, 재현성, 국가 성격 가중치, 분류 유지, 보완 마이그레이션, 편집 보존, 잘못된 원본 거부, FPB 왕복, UI 선택·취소·상태 갱신, 원문 HTML 비해석을 검증했다.
- UI 검증은 jsdom 상호작용 테스트이다. 이전 브라우저 접근 정책 제한으로 실제 브라우저 화면·모바일·E2E 검사는 이번 작업에서 수행하지 않았다. Playwright는 프로젝트 지침에 따라 자동 실행하지 않았다.

## 한계와 후속 작업

상용 규칙서와 확장책 전체, 일반 장비 전체를 포함하지 않는다. 추가 레퍼런스를 확장하려면 원본 자료와 이용·배포 범위를 확인해야 한다. 현재 자동 생성 범위는 기존 요구대로 국가 보물 베리 레어 이상, 도시 상징품 레어 이상이다. 낮은 희귀도 및 아티팩트는 색인에만 포함된다.

원문은 영문이며 한국어 생성 설명은 비공식이다. 아이템 효과를 실제 전투 엔진으로 실행하거나 새 효과의 밸런스를 자동 보증하는 기능은 포함하지 않는다. 수동 수정한 효과와 추가 RP 판정은 GM이 확인해야 한다.

기존 개발 서버의 5173 포트 리스닝을 확인했다. 로컬 코드·빌드 결과만 반영했으며 GitHub push와 공개 사이트 배포는 하지 않았다.
