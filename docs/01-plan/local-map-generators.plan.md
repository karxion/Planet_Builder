# 상세 지도 생성기 통합 기획서

작성일: 2026-10-11

## 1. 목표와 범위

행성 지도에서 도시·마을·던전·동굴·건물을 선택하면 해당 장소의 상세 지도를 열고, 세계 설정과 NPC를 연결한다. 첨부 이미지의 붉은 체크는 City, Village, Cave/Glade, Dungeon, Dwelling 다섯 개다. 체크되지 않은 Realm은 이번 범위에서 제외한다.

행정 분류는 기존 결정대로 마을 → 영지 → 지역 → 국가만 유지한다. 도시·마을은 같은 정착지 엔티티의 규모/유형으로 구분한다. 던전·동굴·건물은 행정 구획이 아니라 장소(POI)와 그 하위 상세 지도다. 종교·문화 데이터를 다시 도입하지 않는다.

## 2. 확인된 외부 리소스

| 대상 | 공식 자료에서 확인한 내용 | 통합 시 적용할 기능 방향 |
|---|---|---|
| [City](https://watabou.itch.io/medieval-fantasy-city-generator) | 크기를 지정한 중세 도시 배치, 스타일 옵션, JSON을 City Viewer로 전달하는 흐름 | 도로망·구획·성벽·시장·항구를 도시 상세 지도로 구성 |
| [Village](https://watabou.itch.io/village-generator) | 마을 생성, 스타일 프리셋, 영구 링크 기반 재현. 작성자는 댓글에서 JSON으로 마을을 다시 불러오는 기능과 서버 API가 없다고 설명 | 도로·하천·농경지·주택·나무를 배치하고 행성의 마을과 연결 |
| [Cave/Glade](https://watabou.itch.io/cave-generator) | 동굴/숲 공터 생성과 옵션 메뉴, 스타일 관련 개발 기록 | 동굴의 입구·통로·수역·공간을 구성하고 야외 공터 모드와 분리 |

| [Dwelling](https://watabou.itch.io/dwellings) | 주택 생성, 평면도 출력 이용 조건. 개발 기록에 청사진 편집·입구·계단·JSON 출력 기재 | 건물 외관과 층별 실내 평면도를 별도 보기로 구성 |

위 표의 오른쪽 열은 우리 제품의 제안 기능이며, 외부 사이트에 동일한 자동화 API가 있다는 뜻은 아니다. 각 생성기의 실제 자동 연동 파라미터, 내보내기 데이터 구조, 임베드 정책은 구현 단계에서 개별 검증한다. 이번 조사에서는 공식 소개·FAQ·개발 기록을 확인했고 다섯 생성기의 모든 편집 동작을 브라우저로 테스트한 것은 아니다.

## 3. 코드와 결과물의 이용 조건

[공식 FAQ](https://watabou.github.io/faq.html)는 생성 결과 이미지의 복사·수정·상업용 RPG 자료 활용을 허용한다고 설명한다. 이는 생성기 프로그램 자체의 복제·재배포 허용과 동일하지 않다. FAQ는 대부분의 현재 생성기 코드를 공개하지 않으며 초기 도시 생성기 소스만 공개했다고 구분한다.

공개된 [TownGeneratorOS](https://github.com/watabou/TownGeneratorOS)는 GPL-3.0이며, README에 최신 기능 일부가 없다고 적혀 있다. 이 코드를 현재 MIT 앱에 그대로 포함하는 방식을 기본안으로 삼지 않는다. 포크/배포안은 적용 범위와 배포 의무를 별도로 검토하고 필요하면 원저작자의 별도 허락을 받는다. 무료 웹사이트라는 이유로 JavaScript 번들·아트·UI를 복사하지 않는다.

**권장안: 외부 생성기 링크 + 결과 가져오기로 먼저 연결하고, 이후 자체 상세 지도 엔진을 단계적으로 구축한다.** “기능을 모방”하는 범위는 생성 원리와 작업 흐름을 참고한 독립 구현이다. 원본 코드나 시각 에셋의 무단 복제는 포함하지 않는다. Watabou 출처 링크는 유지한다.

## 4. 단계별 구현

### 1단계: 장소 연결과 결과 보관

- 정착지/표식 편집기에 `상세 지도` 진입점을 둔다. 행성 → 장소 → 상세 지도 → 방/건물 → NPC로 이동하며 뒤로 돌아올 때 지도 카메라와 선택을 복원한다.
- 장소별 고정 시드와 생성기 종류를 저장하고 외부 생성기는 명시적 클릭으로 연다. 현재 확인된 던전 시드 링크부터 사용한다.
- PNG/WebP 결과 이미지를 사용자가 가져와 해당 장소에 첨부한다. 외부 캔버스의 이미지나 DOM을 자동으로 읽어 오지 않는다.
- SVG는 스크립트·외부 참조·이벤트 속성·foreignObject를 제거하는 검증기가 준비된 후 지원한다. JSON은 생성기별 포맷/버전을 검증하는 어댑터가 있을 때만 지원한다.
- 선택적 iframe은 공급자 정책, 접근성, 키보드 포커스 및 보안을 확인한 뒤 도입한다. 차단되거나 오프라인이면 별도 탭 열기와 이미 저장한 결과 보기로 대체한다.
- 공식 postMessage/API가 없는 상태에서 자동 저장, 양방향 편집 동기화, 원격 결과 자동 수집을 약속하지 않는다. 임베드만으로 오프라인 기능이 생기지도 않는다.

### 2단계: 자체 마을·도시 생성기

- 기존 시드 RNG와 D3/Delaunator 공간 분할을 활용한다. 새로운 기하 라이브러리는 필요한 경우 라이선스·성능을 검토하고 승인 후 추가한다.
- 세계 데이터의 정착지 위치, 규모, 수도 여부, 항구, 인접 하천, 주요 도로, 생물군계를 입력 스냅샷으로 넘긴다.
- 지형 경계 → 주요 도로/교량 → 구획 → 건물 → 농경지/식생 순으로 생성한다. 실제 도로 접점과 수계 연속성을 우선한다.
- 내부 길이 단위는 미터로 고정한다. 행성 지도 좌표와 실내 좌표를 섞지 않고 위치·방향 변환을 어댑터에서 처리한다.
- 잠근 건물/도로/구획은 재생성에서 보존하고 나머지만 다시 생성한다. 행성 재생성 시 상세 지도는 자동 삭제하지 않고 연결 대상 상실 상태를 표시한다.
- 독립 생성 엔진은 DOM을 사용하지 않고 SVG 렌더러와 편집 명령을 분리한다. 큰 생성 작업은 Worker와 취소 기능을 검토한다.

### 3단계: 자체 던전·동굴·건물 생성기

- 던전: 입구에서 모든 주요 방으로 이동 가능한 연결 그래프, 방/복도/문/계단, 다층 연결, GM 전용 메모와 공개 지도 출력.
- 동굴: 유기적인 공간 생성 후 연결 성분 검사, 최소 통로 폭, 고립 공간과 입구 차단 방지. 물과 통로는 별도 레이어로 관리.
- 건물: 외곽 윤곽, 층별 방 분할, 출입구, 층 사이 계단과 동선 검사. 외관 이미지는 실내 평면도와 분리.
- 선택적 격자 크기는 미터로 저장하고 D&D 표시 모드에서 5피트 환산을 제공한다. 세계 지도 거리와 전투 격자 단위를 혼동하지 않는다.
- 생성 결과의 시각 스타일은 기존 RPG 표식과 어울리는 독자적인 선화/재질 프리셋으로 설계한다. AI 이미지는 외관·분위기 이미지에 사용하고 통행 가능성이나 방 배치의 원본 데이터로 쓰지 않는다.

## 5. 데이터 계약 제안

다음은 후속 구현을 위한 설계이며 이번 변경에서 저장 형식을 추가한 것은 아니다.

```ts
interface DetailMap {
  id: string;
  kind: "city" | "village" | "dungeon" | "cave" | "dwelling";
  parent: { kind: "burg" | "marker" | "detailMap"; id: string };
  source: "watabou-link" | "import" | "native";
  seed: string;
  generatorVersion: string;
  sourceUrl?: string;
  inputSnapshot: Record<string, unknown>;
  geometry?: { units: "m"; floors: unknown[] };
  assetIds: string[];
  npcIds: string[];
  revision: number;
  orphaned: boolean;
}
```

- `.fpb`에 버전이 있는 `detailMaps`와 첨부 파일 목록을 확장한다. 이전 파일은 빈 목록으로 마이그레이션한다.
- 장소 ID는 프로젝트 안에서 안정적으로 유지한다. 단순 셀 번호만으로 정체성을 판단하지 않는다. 삭제·재생성 시 끊어진 연결을 명시적으로 복구한다.
- 프로젝트 파일 출력에는 결과 이미지를 포함해 링크가 사라져도 확인할 수 있게 한다. 외부 URL/시드만 있는 자료는 재현이 보장되지 않는다고 표시한다.
- IndexedDB는 메타데이터와 Blob을 분리하고, 프로젝트 다운로드 시 하나의 패키지로 합친다. 저장 용량 제한과 실패를 먼저 검사한다.
- 클라우드에서는 기존 private 스토리지와 revision 충돌 정책을 재사용한다. 파일 업로드 → 메타데이터 확정 → 이전 파일 정리 순서를 유지한다.
- 외부 링크는 공급자 도메인 허용 목록과 URL 파서로 검사한다. 임의 HTML과 iframe은 프로젝트 데이터로 저장/실행하지 않는다.

## 6. NPC 연계

- 기존 D&D 5.5/SRD 기반 NPC 시스템을 재사용하며 상세 지도마다 별도 NPC를 자동 증식시키지 않는다.
- 기존 NPC를 건물·방·던전 구역에 배치하거나 해당 장소의 주민/상인/경비/탐험가를 선택적으로 생성한다.
- NPC 이름, 스탯 블록, 소속 마을은 동일 ID를 참조한다. 방에서 수정한 NPC가 행성의 세계·NPC 화면에도 반영되게 한다.
- 던전 위험도와 전투 난이도는 분리한다. 단순히 방 수로 CR을 결정하지 않으며 SRD 범위와 계산 규칙을 따로 검증한다.
- GM 비밀 메모/NPC와 플레이어용 출력의 포함 여부를 구분한다.

## 7. 완료 기준과 현재 상태

- 같은 시드·입력·생성기 버전의 자체 생성 결과가 같고, 잠금 요소가 보존된다.
- 도시 도로와 하천 접점, 던전 연결성, 동굴 통로 폭, 건물 계단/출구를 자동 검사한다.
- `.fpb` 왕복 저장에서 상세 지도·첨부 이미지·NPC 연결·선택 상태가 보존된다.
- 오프라인, 외부 사이트 차단, 버전 변경, 손상된 파일, 악성 SVG/JSON, 용량 초과를 검증한다.
- 한/영 전환과 1440×900, 1920×1080에서 장소 탐색·복귀·출력 흐름을 실제 브라우저로 확인한다.

**이번 작업에서 구현:** 자원 토큰 50% 표시, 겹치는 정착지/자원/표식의 그룹 표시, 던전 위치 목록·수동 배치·지도 이동·편집 진입, 장소 시드에 따른 Watabou 던전 링크.

**아직 구현하지 않음:** 다섯 생성기의 통합 상세 지도 편집기, 결과 이미지 가져오기와 보관, 자체 생성 엔진, 상세 지도 파일 형식, 방/건물 단위 NPC 배치. 이 문서는 그 구현 순서와 경계를 제안한다.
